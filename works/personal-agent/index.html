个人 agent 记忆系统

把学习日志、踩坑与项目归档收进一个库，让 AI 在我划定的边界里调用。

2026 · v3更新 2026/10/11

这是什么

一套给我自己用的文本记忆库：我学过什么、搞砸过什么、做成了什么，全部进库；AI 只能在我划定的边界内使用它们。

它不是某个软件，是一套约定加一堆 markdown 文件。四个层：

层放什么谁可以改
深度画像全量事实：经历、判断、行为证据只有我确认后才能改
通用画像从深度画像提取的行动版，可外发给第三方 agent同上
工作流协议怎么归档、谁改哪一层、什么时候清算同上
对话归档每一次深度对话的摘要只追加

另加两样：给 AI 看的事实缓存（当前状态、进行中的事、下一步）和事件日志（只追加）。

两条我认为最重要的设计

一、权威只有一份，其余全是指针。 我在好几个客户端里用 AI（opencode、DSH、TRAE、WorkBuddy……），每个客户端都有自己的”规则文件”。我在这些文件里只写指针，权威规则唯一存在一份。

理由很朴素：同一条规则抄成六份，早晚有一份会漂——而漂掉的那份，会以”AI 说的”的形式回到我面前。

二、三流分权。 画像流（我是谁）必须我确认；归档流只许追加、不许改写历史；项目流谁干活谁写。这样”记录”不能反过来篡改”事实”。

它为什么存在

我做的项目几乎都远超我当时的水平——我是那种”知道自己想要什么、但看不懂自己写的是什么”的人。

所以我让 agent 在开发时替我记坑：一条一坑，记到现在有 66 条，我一条都还没翻开过。记它们不是为了冒充经验，是留给以后的自己验收用的——等我走到能看懂的那一天。

一个副产品：双脑

只在”重大决策”这一种场合，主代理会自动识别出对话场合，并开启一个独立的子代理，只做一件事：指出主代理判断里最可能错的地方。

因为同一个模型再问一次不是第二个意见，是同一条思路的延长线——它先给结论，再顺着结论找理由。成本纪律写在规则里：一次最多开一个，不并行、不连环。

边界

  • 不上向量库 / RAG / embedding：md 文件就是全部记忆层。日后如有需要，并且在我的知识水平足够时，我可能会着手落地，
  • 隐私不是”技术安全”，是边界——AI 在边界内调用，而边界由我划。
