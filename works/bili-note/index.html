Bili-note

把视频和音频变成可检索的时间戳文字稿。

2026-08 · v2.1更新 2026/10/11

这是什么

一个跑在本机的 Web 应用：把一个视频链接（或本地文件）丢进去，它把视频和音频变成带时间戳的文字稿，再把文字稿变成能读、能搜、能总结的稿子。

技术上没什么花活：FastAPI + uvicorn 做后端，yt-dlp 负责下载，faster-whisper 转写（large-v3 / large-v3-turbo 两个模型随时切），前端是原生 HTML/CSS/JS，零构建。

它解决的是我自己的问题

我在 B 站和油管上看的东西，价值和长度成正比——一小时的讲座、四十多分钟的课，看的时候记得住，过两周就只剩一个印象。

所以我要的不是”字幕文件”，是一份能跳回去的文字稿：点某一句话的时间戳，视频就跳到那一段。

我自己做进去的几件事

  • 总结在后台跑。 一开始”总结”和”那根连接”是同一个东西：关掉弹窗，连接断掉，总结当场停掉；而且同时只能总结一个。现在总结是一个独立的后台作业，关掉弹窗只等于关掉一个观看窗口——首页每张任务卡各显示各的进度，同时跑几个也没问题。回放是关键：新接上来的窗口会先把已经发生过的事件补一遍。
  • 万字稿：切输出，不切输入。 一趟生成上万字，模型会前紧后松（实测后半段字数只有前半段的 0.93 倍），还会凭空造引用。改成”先出骨架、再逐节展开”之后，引号保真从 55% 回到 100%，末尾不再变薄，而且比原来更快（80 秒 → 52 秒）。
  • 点时间戳跳回视频。 本地视频靠 HTTP Range 请求拖动，B 站链接直接开原页面并带上秒数。
  • 两种输入。 链接下载，或者直接粘一个本地文件路径跳过转写——对已有的十几份文稿做总结，不用重跑一遍。
  • 推理模型的思考过程单独接出来显示。 不接的话，首字延迟 45 秒，界面空白得像卡死了；接上之后 1.8 秒就有东西动。

现在的状态

日常在用。不联网、只花api。它现在是我看长视频的入口。
